1. はじめに

本アプリは、スマートフォンまたはPCのブラウザから利用できる勤怠管理システムです。 利用には以下の2つの URL があります。

用途URL
スタッフ用（出退勤・申請・部署上長承認）https://l91005025-png.github.io/kanko-app/
管理者用（最終承認・集計・設定・部署管理）https://l91005025-png.github.io/kanko-app/admin.html
推奨ブラウザ: Chrome / Safari / Edge の最新版。
通信環境: インターネット接続が必要（社内Wi-Fi または モバイル回線）。

権限の3層構造

権限できること使うアプリ
スタッフ打刻・自分の勤怠閲覧・申請スタッフ用
部署上長上記＋自部署の有給を一次承認スタッフ用
管理者（総務）すべての操作・最終承認・設定変更両方

2. アプリのインストール

本アプリは PWA（Progressive Web App） に対応しており、スマホのホーム画面に追加することで通常のアプリのように起動できます。

iPhone ユーザー必読: プッシュ通知を受信するには 必ず「ホーム画面に追加」 が必要です。Safariのタブで開いたままだと通知が届きません（iOS 16.4 以降必須）。

2.1 iPhone（Safari）の場合

1Safari でスタッフ用 URL を開く
2下部メニューの 共有ボタン（□に↑）をタップ
3メニューから 「ホーム画面に追加」 をタップ
4名前を確認して 「追加」
5ホーム画面に追加されたアイコンから起動

2.2 Android（Chrome）の場合

1Chrome で URL を開く
2右上の ⋮（3点メニュー） をタップ
3「ホーム画面に追加」 または「アプリをインストール」を選択

2.3 PCの場合

ブックマークに登録するだけで使えます。Chrome / Edge ならアドレスバー右端の「インストール」アイコンからアプリ化することも可能。

10. 【部署上長】有給を一次承認する

あなたが部署上長に設定されている場合、「申請」タブの上部に「部署上長として承認」セクションが表示されます。

自部署の有給を一次承認してください。承認後、総務へ進みます。

対象日: 2026-05-20

▲ 部署上長承認セクション

承認の流れ

1申請が出るとプッシュ通知が届く
2通知をタップしてアプリを開く
3「申請」タブの上部に承認待ちが並ぶ
4内容を確認して「承認」または「却下」
5承認すると総務（管理者）へ自動で回る
あなた自身の有給申請は、自分で承認することはできず管理者が直接承認します。
却下した場合は、申請者本人にも自動でプッシュ通知が届きます。
却下理由は申請時のダイアログで添えられます（任意）。

1月次サマリまたはスタッフタブで「勤怠」をクリック
2日別の打刻時刻・労働時間・残業時間が表示

13.2 モーダルで打刻を修正する

編集モーダルの特徴:
・出勤時刻・退勤時刻は 時刻ピッカー（HH:MM） で直感的に入力
・入力中に「労働 ◯:◯◯ / 残業 ◯:◯◯」を自動プレビュー
・「記録を削除」で当日の勤怠記録自体を削除も可能
1「編集」をクリック → モーダルが開く
2モーダル上部に「氏名 / 日付」と現在の打刻時刻が表示
3出勤時刻・退勤時刻を時刻ピッカーで入力
4下部のプレビュー領域に労働時間・残業時間が自動表示
5必要なら備考を入力
6「保存」クリックで反映 / 「記録を削除」で当日の記録ごと削除
すべての編集・削除は 監査ログ に記録されます（誰が・いつ・何を・何から何に変えたか）。
月締めロック済みの月を編集する場合は警告ダイアログが出ます（強制編集も可能だが監査ログに残ります）。

スタッフからの「打刻修正」申請を反映する場合

  1. 申請タブで「打刻修正」申請を確認
  2. 申請者の対象日について、勤怠タブ → 該当スタッフ → 編集モーダルで修正
  3. 申請タブに戻って当該申請を「承認」

14.1 二段階承認（有給）

有給申請は 部署上長 → 管理者 の順に承認されます。両方承認されて初めて「承認済み」になります。

段階表示管理者の操作
1部署上長承認待ち原則部署上長が処理。代理として管理者が直接最終承認も可
2総務承認待ち「総務として承認」または「却下」
完了承認勤怠に反映、有給残数 -1日（半休は -0.5日）

14.2 単一承認（有給以外）

シフト休・半休・残業・打刻修正などは管理者の承認のみで完了します。

14.3 承認後の取消・編集・削除

操作動作
取消（申請中へ戻し）有給残数を自動で戻し、申請中ステータスに戻す
編集日付・理由・種別・ステータスを修正
削除申請を完全削除（誤申請の場合に使用）

14.4 却下時のコメント

却下時にダイアログで理由を任意入力できます。スタッフへのプッシュ通知＋申請履歴で表示されます。

14.5 承認待ちバッジ

「申請」タブのアイコンに、管理者が処理すべき申請件数のバッジが表示されます。

15. 【管理者】カレンダータブ

「カレンダー」タブで全社の休暇予定を月単位で俯瞰できます。

  • 部署フィルタで特定の部署だけ表示
  • 「承認済のみ」/「承認＋申請中」を切替
  • 休暇種別ごとに色分け表示
使い時: シフト調整・人員配置の検討、申請承認前に他の人の予定確認。

16. 【管理者】設定タブ

設定タブには以下のセクションが上から順に並びます（使用頻度の高い順）。

セクション用途頻度

3. 月締めロック確定した月の改ざん防止月次

16.1 有給休暇 残数管理

全員に一括付与（年初など）

1付与日数を入力（例: 10）
2動作を選ぶ:
  • 残数に加算: 既存残数に追加（例: 5日残 + 10付与 → 15日）
  • 残数を上書き: 全員を指定日数にリセット
3「全員に適用」→ 確認 → OK

個別に修正

1スタッフ一覧で対象者を探す（氏名検索・部署フィルタ・残数少ない順ソート可）
2右の数値ボックスに新しい残数を入力
3「更新」
「5日未達のみ」のチェックボックスで、有給5日取得義務未達のスタッフだけを抽出可能（労基法対応）。

16.2 シフト休 残数管理

シフト休は 有給とは別軸 で残数管理されます。シフト休申請が承認されると -1日、取消されると +1日 自動で増減します。

全員に一括付与

1「シフト休 残数管理」セクションで付与日数を入力（例: 12）
2動作（残数に加算 / 残数を上書き）を選ぶ
3「全員に適用」→ 確認 → OK

個別に修正

1スタッフ一覧で対象者を探す
2右の数値ボックスに新しい残数を入力
3「更新」
既存スタッフでまだ一度もシフト休残を付与していない場合、表示は 0日 です。初回付与時に過去取得分を考慮した日数で入れてください（過去の承認分は遡って自動差引されません）。

16.3 月締めロック

給与計算済みの月など、確定した月の変更を抑制したい時に使います。

1「締済の月」テキストエリアに 2026-04 のように1行1月で入力
2「月締めを保存」
ロックされた月を変更しようとすると警告ダイアログが出ます。強制編集は監査ログに記録されます。

16.4 部署管理

部署を追加する

1「部署追加 / 編集」フォームに記入:
  • 部署名（例: 営業部）
  • 始業時刻・終業時刻
  • 休憩（分）・所定労働時間（分）
  • 定休パターン（次節）
  • 固定休日（毎年同じ日付・任意）
2「保存」

部署を編集する

「部署一覧」の各部署で「編集」 → フォームに値が入る → 修正して「保存」。

部署を削除する

所属スタッフがいる場合は確認ダイアログが出て、削除すると全員「未所属」に戻ります。

16.5 公休パターンと月別調整

会社の公休が「毎週日曜・第1月曜・第3土曜」のように複雑な部署にも対応。「今月だけ」の例外も設定可。

定休パターンの設定

部署編集中の「定休パターン」セクション:

1「＋ パターン追加」をクリック
2頻度を選ぶ: 毎週 / 第1 / 第2 / 第3 / 第4 / 第5 / 最終
3曜日を選ぶ
4必要な数だけ繰り返す
5「保存」
例: 「毎週日曜」「第1月曜」「第3土曜」を組合せると、それら全てが部署の公休になる。

月別の例外調整

「今月の第1月曜は出勤、代わりに第2月曜を休みにする」等の臨時調整。

1部署を編集中にすると下に「月別の公休調整」カードが現れる
2調整したい月を選択して「表示」
3カレンダーで日付セルをクリック:
  • 既定で休セル → クリックで「平日に取消」
  • 平日セル → クリックで「追加で休にする」
  • もう一度クリックで例外を解除し既定に戻る
4クリックごとに自動保存
月別調整はその月に対してだけ有効。翌月は再び元の定休パターンが適用されます。

16.6 監査ログ

勤怠・申請・有給残数・会社共通設定のすべての変更履歴 を記録。労務監査や紛争対応時の証跡として活用できます。

表示と展開

  • 最新50件の操作履歴が一覧表示される（要約: 「○○の有給申請(2026-05-20)を承認」など）
  • 各行の「▼ 詳細」をクリックすると、変更前/後の値が展開表示される
  • 変更前後のJSON内のスタッフIDは 自動で氏名に置換される（読みやすさのため）

絞り込みとCSV出力

  • コレクション（勤怠 / 申請 / スタッフ・有給 / 全て）でフィルタ可
  • 「CSV出力」で全件を労務監査用にダウンロード可能

16.7 会社共通のデフォルト設定

未所属スタッフ・未設定の部署が使用する基準値、及び全社共通の数値を設定します。

項目用途
所定労働時間（分）1日の所定労働時間。これを超えた分が残業
会社全体の祝日リスト1行1日付（2026-01-01 形式）
会計年度開始月有給の取得期間カウントの起算月
有給最低取得義務（日）労基法の年5日取得義務（デフォルト5）
残業 注意ライン（h/月）36協定の注意レベル（デフォルト36）
残業 上限ライン（h/月）36協定の上限（デフォルト45）

16.8 背景画像（このブラウザのみ）

管理者画面の背景に画像を設定できます。ブラウザに保存される個人設定で、他のスタッフには影響しません。

1画像ファイル（JPG/PNG/WebP・2MB以下推奨）を選択 or 画像URLを入力
2不透明度スライダーで透け具合を調整（90%前後推奨）
3不要になったら「背景を解除」

17.1 月次勤怠CSV（5形式）

形式用途

18. 【管理者】退職者を削除する

削除はワンクリックで実行されます。 取消できないため、本当に削除してよいか確認してから実行してください。

手順

1「スタッフ」タブで該当スタッフを探す
2右端の 「削除」 ボタンをクリック
3確認ダイアログで「OK」
4「削除しました（Authアカウント含む）」と表示されれば完了
この削除では:
  • Firebase Authentication のログインアカウントを削除（再ログイン不可に）
  • users ドキュメントを削除（社内データから消える）
過去の打刻・申請履歴は 残ります（労務監査・5年保管義務対応）。完全削除したい場合はFirebase Consoleから手動で消してください。

19. データ保護とバックアップ

19.1 日次自動バックアップ

毎日 03:00 JST に全データ（勤怠・申請・スタッフ・部署・設定・監査ログ）を自動で JSON 形式でクラウドストレージにバックアップします。
項目内容
実行時刻毎日 03:00 JST
保存先Firebase Storage (gs://kintai-app-95b49.firebasestorage.app/firestore-backups/)
形式JSON（人間が読める形式、Firestore Timestamp は ISO 文字列に変換）
保持期間90日（自動ローテーション。古いものから削除）
復元方法Firebase Console から JSON をダウンロード → スクリプトで Firestore にインポート（管理者作業）
通常時は意識する必要はありません。誤削除や障害時の復元用です。
バックアップが正常に動作しているかは Firebase Console → Storage → firestore-backups/ フォルダで確認できます。

19.2 打刻時刻の改ざん防止

出勤・退勤の自動打刻時刻は Google サーバーの時刻で確定されます。端末（スマホ・PC）の時計を変更しても改ざんできません。労務紛争時の証拠力があります。

19.3 監査ログによる追跡

勤怠・申請・有給残数・会社共通設定の 全変更 が「誰が・いつ・何を・何から何に変えたか」記録されます（設定タブの「監査ログ」参照）。

19.4 法定保管期間

労務関連データの法定保管期間は5年です。日次バックアップ（90日保持）に加えて、月次でCSVを出力して総務側でも保管することを強く推奨します。

20. よくある質問

Q1. パスワードを忘れたら？

管理者に連絡してください。Firebase Console からパスワードリセットメールを送信できます。

Q2. 本日の打刻を間違えたら？

「打刻」タブ下部の「手動修正（本日分）」で本日分は自分で修正できます。過去の日付や追加で修正したい場合は「申請」タブの「打刻修正」で管理者に申請してください。

Q3. 在宅勤務でも打刻できる？

はい、インターネット接続があればどこからでも可能です。

Q4. 通知が来ない

  1. iPhone の場合「ホーム画面に追加」したアプリから起動しているか
  2. 「打刻」タブの通知許可カードで「✓ 通知が有効です」と出ているか
  3. ブラウザ設定で通知がブロックされていないか

Q5. 部署が変更になったら？

管理者がスタッフタブで「部署」を変更してください。即座に新部署の勤務時間・公休パターンが適用されます。

Q6. 部署上長が退職した場合は？

管理者が新しい上長を立てるまで、その部署の有給申請は管理者が直接承認します（自動的にエスカレーション）。

Q7. 半休を取ったら有給残数は？

承認時に -0.5日 として自動計算されます。

Q8. 有給残数を超えて有給申請すると？

申請時に確認ダイアログが出ます。原則は事前に管理者へ相談してください。

Q9. 画面が古いまま更新されない

強制リロード（Cmd+Shift+R / Ctrl+Shift+R）でデータが最新化されます。

Q10. データのバックアップは？

毎日深夜3時に自動バックアップ（90日保持）されています。加えて月次CSVを総務側でも保管を推奨（労務関連は法定5年保管）。

Q11. 打刻時刻は改ざんできる？

自動打刻は Google サーバーの時刻で確定 されるため、端末の時計を変えても改ざんできません。スタッフ画面の「手動修正（本日分）」での編集はすべて監査ログに記録されます。

Q12. 監査ログでは何がわかる？

勤怠・申請・有給残数・会社共通設定のすべての変更履歴（誰が・いつ・何を・変更前後の値）が記録されます。「設定」タブの「監査ログ」で最新50件を確認＋CSV出力可。

Q13. 月締めロック後に変更が必要になったら？

編集自体は可能ですが、警告ダイアログが出て、強制編集の事実が監査ログに記録されます。

Q14. 連続日申請（複数日の有給など）はできる？

申請画面で「期間」を選ぶと開始日〜終了日を指定して最大31日分を一括申請できます。自部署の公休は自動的に除外されます。

Q15. シフト休と有給の違いは？

シフト休は 有給とは別の残数 で管理されます（管理者が設定タブで個別に付与）。有給は法定の年次有給休暇、シフト休は会社独自のシフト調整用休暇という位置づけです。
シフト休申請は 理由欄が任意（空欄でも申請可能）です。承認時に -1日、取消時に +1日 自動で増減します。

Q16. シフト休はどうやって付与する？（管理者向け）

「設定」タブの「シフト休 残数管理」セクションから、有給と同様に一括付与・個別編集が可能です。
既存スタッフでまだ一度も付与していない場合は表示が 0日 ですので、初回付与時に過去取得分を考慮した日数で入れてください。
